## [Unreleased]

### Added

- `kbms:doctor` gained a **Queue worker configuration** check: it fails when the running `queue:work` worker started before the current `.env` was last written (naming `php artisan queue:restart` as the remedy), reports **could not determine** as a failure — never a pass — when the worker's state cannot be established via `ps`/`lsof`, and passes without duplicating the existing queue-connection check when no worker is running at all.
- Calendar-as-todo (FR-024): an event whose title starts with `[]`/`[ ]` renders as an open todo and one starting with `[x]`/`[X]` as a completed one, with the marker stripped from the display and replaced by a checkbox glyph on the agenda, the calendar and the meeting detail page. The marker is recognised only at the very start, with leading whitespace forgiven, so `Review [x] doc` stays an ordinary meeting; a title that is only a marker renders as `Untitled` rather than as a blank row. An open item whose end time has passed reads as **overdue**, re-derived on every render — so it goes late on its own on the next self-refresh, with no reload. A done item is never overdue however old, a cancelled occurrence is never overdue (cancelled wins over late), and an all-day item turns overdue only once its day has ended. Status is **read-only and derived**: no column, no migration, no write-back, and no change to `kbms:sync-calendar` — items are ticked in Outlook. The marker vocabulary is hardcoded with no `KBMS_*` key. Todo status is a third independent channel alongside coverage and rule colour, using its own colour token distinct from every rule colour, and is carried by the glyph and the accessible name as well as by the treatment, so it never rests on colour alone. Parsing adds no per-occurrence queries. Deliberately absent: no in-app toggle, no filtering by status, no overdue badge or pinned strip, and no notification of any kind.
- Rule-based event colouring on the calendar and the agenda (FR-023): an ordered rule list in `config/kbms.php` tints occurrences by the mirrored feed fields, so a category of meeting is recognisable before its title is read. Each rule names a field (`summary`, `location`, `description`, `organizer`), a condition (`contains` — case-insensitive substring — or `empty` — null, absent, or whitespace-only), a colour from a closed six-token palette resolved in the stylesheet, and a short label. Array order is the priority and the first match wins; there is no priority key, no split fill, no `KBMS_*` key, no database table, and no management UI. A rule naming an unknown field, condition, or colour — or a raw CSS value — is dropped rather than honoured, leaving its events uncoloured and the page rendering; an empty list is the supported "off" state. Rule colour, note/transcript coverage, and cancelled styling are three independent channels that render together, and every rule's label appears in both page legends (generated from the configuration) and in each matched event's accessible name, so colour never carries the meaning alone. Colouring costs no additional query: rules are matched against columns the agenda and calendar queries already load. Ships with two defaults — `summary` contains `PING` → yellow, then `location` empty → purple.
- Self-refreshing agenda and calendar views: both scanning surfaces bring themselves up to date on a fixed ~60 second cadence while their tab is visible, so a mirror refreshed by the background sync appears without a reload. The refresh is silent by design — no toast, banner, spinner, announcement or page reload — and preserves scroll position, the agenda's `?date=` anchor and Jump-to field, and the calendar's current view, anchor date and keyboard-focused day cell. Time-derived chrome re-derives with each refresh, so the `Now` divider moves as meetings pass and the relative sync wording stays accurate on a page left open for hours. Refreshing pauses outright while the tab is hidden and fires a single catch-up on return; a failed refresh leaves the last good render on screen rather than blanking, erroring, or dropping to an empty state, and sync failures keep being reported only by the existing sync pill and alert. The cadence lives in `resources/js/self-refresh.js` and is deliberately hardcoded — no `KBMS_*` key and no operator-facing control. The meeting detail page is deliberately excluded, because a timed re-render there would risk interrupting the notes editor.
- Local Claude Code launch bridge: a question typed against a meeting is handed, together with the resolved transcript path, to the operator's own `KBMS_CLAUDE_LAUNCHER` script as an argument array — never an interpolated shell string — so quotes, newlines, backticks, `$(...)` and other shell metacharacters reach the script as a single intact argument. The invocation runs inside a queued job rather than the web request, waiting up to `KBMS_LAUNCH_TIMEOUT_SECONDS` (default `30`) for the script to spawn its own terminal window and return; the launcher's exit code is recorded on the launch row and shown on the meeting page. Every blocked precondition (launcher unset, missing, not executable; no transcript linked, rejected, or unreadable; an empty or over-length question) names its own configuration key or action rather than a generic error, and the exact invocation is rendered and copyable so the operator can run it manually. The application never captures Claude's reply.
- `KBMS_LAUNCH_TIMEOUT_SECONDS` (default `30`) and `KBMS_QUESTION_MAX_CHARS` (default `8000`) configuration variables.
- Transcript linking and in-place preview: a configurable resolver maps a meeting to at most one candidate file under `KBMS_TRANSCRIPTS_PATH` via `KBMS_TRANSCRIPT_PATTERN`, tolerating start-time drift within `KBMS_TRANSCRIPT_TOLERANCE_MINUTES` (default `10`) and never guessing when the window yields multiple candidates — the operator chooses instead. A manual override (in-app file picker, no free-text path) always wins over the convention, and clearing a link writes an explicit unlink tombstone rather than deleting the row. The meeting detail page reads and renders the resolved transcript in place — bounded to `KBMS_TRANSCRIPT_PREVIEW_BYTES` (default 2 MiB) with a truncation notice, Markdown through the same hardened converter as notes, plain text escaped — without ever copying content into the database. Eight distinct states (not configured, missing, ambiguous, linked, broken, unreadable, rejected, suppressed) each carry their own wording. The agenda's `Transcript` badge is now live, backed by a batched lookup that costs exactly one additional query and one directory listing per agenda page regardless of week density.
- `KBMS_TRANSCRIPT_TOLERANCE_MINUTES` (default `10`) and `KBMS_TRANSCRIPT_PREVIEW_BYTES` (default `2097152`) configuration variables.
- Personal notes on a meeting: an autosaving Markdown note surface keyed on the occurrence's natural key (`event_uid` + `event_recurrence_id`), never the calendar row's surrogate id — a note written on one occurrence of a recurring series never appears on its siblings, and survives a resync that retitles, reschedules, relocates or cancels the meeting upstream, or even an outright deletion and re-creation of the mirrored row. Write/Preview tabs render the rendered Markdown through a hardened converter that escapes embedded HTML and neutralises unsafe links instead of executing them. A failed autosave surfaces a "Not saved" indicator with a retry action and never discards typed content. An explicit confirmed "Delete notes…" dialog is the only path that removes a note; clearing the editor is an edit, not a deletion. Meetings carrying notes are flagged in the agenda, so the list doubles as a coverage map, with the batched lookup costing exactly one additional query per agenda page regardless of week density.
- Agenda: a chronological, keyboard-navigable triage view of mirrored meetings defaulting to today's 7-day window, with forward/back range navigation and a date jump. Day groups are always rendered, including empty ones, so a genuinely quiet day reads as trustworthy rather than unsynced. Multi-day events — all-day and timed alike — render once, clamped to their first visible day and labelled with the days they span; overlapping timed events both render, correctly ordered, with an event still in progress at midnight sorted ahead of the meetings that start that morning. A bookmarked range URL carrying an unreadable date falls back to today instead of erroring.
- Meeting detail page addressed by a canonical occurrence route (`source_uid` + `recurrence_id`, never a surrogate id a resync can change), showing every mirrored feed field read-only in a surface visually distinct from the operator-owned column.
- "Open in Outlook" call-to-action: prefers a feed-carried `event_url`, falls back to the configurable `KBMS_OUTLOOK_URL_TEMPLATE` (placeholders `{date}`, `{time}`, `{datetime}`), and disables itself with a visible reason when neither is available — never a broken link. A Teams join link, when present, is offered as a distinct action.
- Sync health in the app shell: a status pill on every page shows the last successful sync in relative and absolute form, flags a **stale** mirror after `KBMS_SYNC_STALE_MULTIPLIER` × `KBMS_ICS_SYNC_MINUTES` without a success even when nothing has failed, and reads **never synced** when no run exists. A failure banner prints the stored error and names `KBMS_ICS_URL`, so a broken feed never requires opening `storage/logs`.
- Manual resync from the sync pill — dispatches `SyncCalendarFeed` without a duplicate or overlapping run (`ShouldBeUnique` plus an in-flight guard), and abandons a run whose worker died as failed after `KBMS_SYNC_STUCK_AFTER_SECONDS` instead of leaving it spinning forever.
- `KBMS_SYNC_STALE_MULTIPLIER` (default `3`) and `KBMS_SYNC_STUCK_AFTER_SECONDS` (default `300`) configuration variables.
- Scheduled ICS calendar ingestion (`kbms:sync-calendar`): a queued job fetches the subscribed feed with conditional GET, expands recurring series into individually addressable occurrences (`calendar_events`), and upserts them without ever deleting a row — disappearances and `STATUS:CANCELLED` both mark `cancelled_at` instead. Every run is recorded in `calendar_sync_runs`, pruned after `KBMS_SYNC_RUN_RETENTION_DAYS`.
- `php artisan kbms:doctor` — verifies the ICS feed, transcripts directory, launcher script, queue connection, scheduler registration and timezone, with a remediation hint per failure and a non-zero exit code.
- Application scaffold: Livewire + Flux starter kit, KBMS app shell with theme tokens and Workspace/Later navigation
- SQLite database, `database` queue driver, and a scheduled `kbms:sync-calendar` stub
- Full `KBMS_*` configuration surface with documented defaults
- Loopback-only access control with a configurable override
- Actionable error page for a missing or unreadable SQLite database file

### Changed

- `kbms:doctor`'s ICS feed check now parses the body with `sabre/vobject` instead of string-matching the envelope. A feed that parses cleanly with zero events now **passes** — it previously failed, since string-matching had no way to distinguish an empty-but-valid calendar from a wrong subscription URL.
- Transcript filename convention is now `{date}_{time}_{slug}`, with `Ymd` dates and underscore-separated slugs, matching the operator's transcription pipeline output. **Breaking for unlinked files:** the previous hyphenated `Y-m-d` convention is no longer recognized — such filenames are simply not indexed. Already-linked transcripts are unaffected, since the stored path is read directly. Same-drift candidates are now ordered by slug **prefix** rather than exact equality. Convention resolution and the manual picker now index `.md` files only — a pipeline emitting a `.md` + `.txt` pair per recording was otherwise doubling every candidate and turning single-transcript meetings ambiguous. **Breaking for `.txt`:** a `.txt` sibling is no longer auto-linked or offered by the picker; transcripts already linked to a `.txt` path are unaffected and still render as escaped plain text.

### Fixed

- `TranscriptPattern::parse()` no longer silently rolls an impossible calendar date (e.g. `20261345`) forward into the following month — such a name now parses to `null`, the same as any other name the convention does not claim.
- The `.txt` context file handed to the launcher script is now verified for containment and readability before a launch proceeds, closing a gap where the extension swap happened after every check had already run. A missing or unreadable `.txt` sibling now blocks the launch with its own named reason instead of dispatching a job that opens a path to nothing.
- A launch dispatched with a launcher script configured, but refused by a queue worker running against a stale `.env`, is now blocked with a distinct message naming the worker as stale and `php artisan queue:restart` as the remedy — never with `` `KBMS_CLAUDE_LAUNCHER` is not configured. ``, which sent the operator to an `.env` that was already correct.

### Removed

- Starter-kit authentication surface (Fortify, passkeys, 2FA, `User` model, login/register/settings views) — this product has no accounts by design
