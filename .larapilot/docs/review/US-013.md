## Robert (code review)

- `- [High] FIXED` **A `null` summary took the whole calendar feed down with a TypeError.** `CalendarEventPayload::from()` passed `$event->summary` straight into a `string $title` parameter and into `accessibleName(string $title, …)`. Any single occurrence with no `SUMMARY` would 500 `GET /calendar/events`, blanking the grid for every other event in the window. Pre-existing since US-008 — but "a `null` summary parses to 'not a todo' and errors nothing on the feed, the agenda, or the detail page" is one of **US-013's own acceptance criteria**, so it was in scope here. Reproduced through tinker before fixing, not assumed. Fixed by giving `MeetingTodo::displayTitleFor()` the display-title rule for both surfaces, so the empty-title fallback holds for a marker-only summary and a genuinely null one alike. Two regression tests added (`test_a_null_summary_errors_nothing_on_the_feed_the_agenda_or_the_detail_page`, `test_a_null_summary_renders_untitled_rather_than_a_blank_chip`).
- `- [Medium]` **The channel contract now has three members and is still enforced by CSS property, not by convention.** Todo owns a glyph, the title's weight and strike, and `color` on the glyph and status tag. It sets **no** `background`, so US-012's rule fill survives underneath it, and it targets `.fc-event-title` / `.kb-row__title` rather than the chip or row element, so it cannot fight the chip-level rule `color`. This is the single most important invariant to re-check on any future CSS edit here: a `background` on a `kb-ev--todo-*` or `kb-row--todo-*` rule would silently eat the rule colour. There is an explicit test (`test_an_overdue_rule_coloured_annotated_occurrence_renders_all_three_channels`) asserting all three on both surfaces plus the full accessible name.
- `- [Medium]` **Cancelled-wins-over-late is guarded in the parser, not in CSS.** `MeetingTodo::for()` refuses to mark a cancelled occurrence overdue, so `kb-ev--todo-overdue` and `kb-ev--cancelled` can never co-occur. The `:not(.kb-ev--cancelled)` / `:not(.kb-row--cancelled)` guards on the overdue rules are therefore belt-and-braces, added for the same reason US-012 added its own: so a future reordering of the stylesheet cannot produce a contradiction. Both the parser rule and the rendered outcome have tests.
- `- [Low]` `AgendaRow` derives `$todo` and `$displayTitle` in its constructor rather than accepting them — deliberately the mirror image of US-012's `$colourRule` default. There, the default is what *excludes* the detail page; here, constructor derivation is what *includes* it, since `MeetingController` builds an `AgendaRow` too. Both docblocks say so, because the asymmetry looks like an inconsistency otherwise.
- `- [Low]` The regex alternation sits **inside** the brackets (`\\[(?:\\s*|x|X)\\]`) so it must consume everything up to `]`. That is what makes `[ x ]` an ordinary title rather than a sloppily-typed todo, and it is the kind of detail a later "simplification" would break — documented on the constant and covered by `test_a_marker_outside_the_accepted_set_is_ordinary_text`.
- `- [Low]` The agenda glyph is rendered **outside** `.kb-row__title`, so the title element still contains exactly the title. That keeps `AgendaPageTest`'s existing `kb-row__title">{summary}` row-matching helper working without churning a pre-existing test.
- `- [Low]` `resources/js/calendar.js` needed **no** change: the state class arrives through FullCalendar's own `classNames`, the glyph is CSS `::before`, and `eventDidMount` already writes `accessibleName`. Verified rather than assumed.
- `- [Low]` No N+1 and no query-shape change. Parsing reads `summary`, `ends_at` and `cancelled_at`, all already hydrated. Proven with `DB::listen` on both surfaces across a 30-occurrence window, with and without markers.
- `- [Low]` Git discipline: one atomic Conventional Commit per task (`TASK-00`…`TASK-08`) plus one `fix(US-013)` for the review finding above, each carrying the spec id, no commits on `main`/`develop`, no push (correct for `git_mode: GITFLOW`).
- `- [Low]` **No migration, column, index, model, factory or seeder was touched** — an explicit out-of-scope item, and the absence is part of the deliverable rather than an omission.

## Lars (security)

- `- [Low]` No new route, no new request parameter, no authorization surface, no persistence change, no dependency change. The whole spec is a read-time parse of data already mirrored.
- `- [Low]` The marker vocabulary is a hardcoded constant, not configuration and not user input over HTTP, so there is no path by which an untrusted value reaches the regex. The pattern itself is a fixed literal with no user-supplied fragment — no ReDoS surface, and `preg_match` is called once per occurrence with a bounded, anchored pattern.
- `- [Low]` `displayTitle` is derived from the mirrored `summary`, which originates in the operator's own Outlook feed, and is rendered through Blade's `{{ }}` (escaped) on the agenda and detail page, and through JSON into FullCalendar's own text rendering on the calendar. The glyph is CSS generated content and carries no data. No new injection surface.
- `- [Low]` **The `null`-summary fix is a small availability improvement**: one malformed feed occurrence can no longer 500 the calendar feed for the whole window.
- `- [Low]` Contrast: `--kb-todo-overdue` reuses the same inherited lightness pairs as every other `--kb-*` token (`0.45`/`0.955` light, `0.80`/`0.28` dark), so AA carries over by construction. Hue `40` is deliberately clear of `--kb-danger` (`25`), `--kb-warn` (`70`/`80`) and both shipped rule colours, satisfying the spec's "never a token that collides with a configured rule colour".
- `- [Low]` Overdue is carried by three independent signals — the `☐ !` glyph shape, the accessible name wording, and the colour — so it survives both for a reader who cannot see the treatment and for one who cannot distinguish the hue.
