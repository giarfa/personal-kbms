- [Critical] `resources/views/livewire/transcript-panel.blade.php:112` (TASK-09) — `onclick="navigator.clipboard.writeText('{{ $path }}')"` interpolates the transcript's absolute path into a raw inline JS attribute via plain Blade `{{ }}`. ## Lars (security)

Reviewed the same diff for OWASP Top 10, with focus on path traversal (the new filesystem surface) and XSS (the new render surface).

- [High] `resources/views/livewire/transcript-panel.blade.php:112` and `:141` — JS-context injection via unescaped-for-JS filename/path interpolation, independently confirmed (same root cause Robert flagged as Critical/High): Blade's `{{ }}` protects the HTML-attribute delimiter but not a JS string literal nested inside it once the browser HTML-decodes entities. Neither `TranscriptsDirectory::resolve()` nor `pickerFiles()` reject a literal `'` in a filename — only `/`, `\`, `..`, and NUL are blocked. Fix: `Illuminate\Support\Js::from()` (the `@js` directive) for both interpolations.
- [Informational — verified correct] Path traversal / containment (`TranscriptsDirectory::contains()`/`resolve()`): lexical canonicalization + prefix-with-separator check + `realpath()` symlink check; `resolve()` also hard-rejects `/`, `\`, `..`, NUL pre-join. `TranscriptReader::read()` revalidates containment on every call, not only at link time, correctly handling the TOCTOU concern for a changed `KBMS_TRANSCRIPTS_PATH`. One noted residual: a check-then-open TOCTOU window between the containment/`is_file`/`is_readable`/`filesize` checks and `fopen()` — low severity, requires filesystem write access to the transcripts directory already (single-operator, localhost-only app) — not raised as a fresh finding.
- [Informational — verified correct] XSS in transcript content: `.md` renders through `MarkdownRenderer` (`html_input: escape`, `allow_unsafe_links: false`, bounded nesting); `.txt` is wrapped in `HtmlString(e($bounded))`. The `{!! $content->rendered !!}` in the Blade view only ever receives pre-sanitized `HtmlString` from these two paths.
- [Informational — verified correct] Resource exhaustion: `TranscriptReader` never uses `file_get_contents()`; bounded `fopen`+`fread($handle, $limit+1)` with UTF-8-safe truncation via `mb_strcut`.
- [Informational — verified correct] `link(string $filename)` re-validates the client-supplied filename server-side via `TranscriptsDirectory::resolve()` before persisting — does not trust the picker's server-rendered list.
- [Informational — verified correct] `MeetingTranscript::$guarded = []` is safe: no HTTP endpoint mass-assigns it, only Livewire component methods and the factory write with hardcoded key sets.
- [Informational] No new Composer dependency (`composer.json`/`composer.lock` unchanged). No new public route; `security.txt`/`SECURITY.md` posture unchanged (still localhost-only, no exposed API surface added — consistent with the prior accepted-risk determination).
