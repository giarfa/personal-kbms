- [Low] `app/Livewire/MeetingNotes.php` — `render()` unconditionally ran `MarkdownRenderer::render($this->body)` even in Write mode, so every debounced keystroke re-rendered Markdown that wasn't displayed. Harmless at this scale, but avoidable. **Fixed** (`2b98423`): gated on `$mode === 'preview'`.
- [Low, accepted] `MeetingController` + `MeetingNotes::mount()` — the detail page issues two separate single-row `meeting_notes` reads (one via `MeetingCoverageLookup::forOccurrence()` for the badge, one via `MeetingNote::forOccurrence()` in `mount()` for the editor body). Both are single-row indexed lookups; consolidating would add coupling between the controller and the Livewire component for no measurable cost. Left as-is.
- [Low, accepted] `resources/views/livewire/meeting-notes.blade.php` — the `<flux:modal>` is wrapped in `@if ($hasNote)`, and `deleteNote()` flips `hasNote` to `false` in the same request that closes it, so Livewire's re-render removes the modal element rather than letting Flux's own close animation/focus-return finish first. Functionally correct (delete succeeds, focus returns to the trigger per Flux's own handling — verified in the component test), but flagged for the manual keyboard-only pass the plan's Test Strategy already calls for at this bar.
- [Informational, test hygiene only] `tests/Feature/MeetingNotesTest.php`'s forced-failure test calls `MeetingNote::flushEventListeners()`, which clears *all* listeners on the model, not just the injected `saving` closure. Harmless today — no other listener is registered on `MeetingNote`, and Laravel's per-test fresh application container means nothing leaks across tests anyway (confirmed: full suite green). Worth a scoped removal if a real Observer is ever added to this model.
- [Informational] Plan adherence confirmed: no FK or Eloquent relation between `CalendarEvent` and `MeetingNote` (grepped clean); every read goes through `scopeForOccurrence()` or the batched `MeetingCoverageLookup`; no `isPast()`/state gate anywhere in the editor (grepped clean); a write failure leaves `$body` untouched (never reassigned from the database on the error path); `deleteNote()` bypasses `save()`/`updatedBody()` so deleting cannot recreate the row; the agenda issues exactly two queries per page regardless of density (`DB::listen` count test + confirmed by reading `AgendaQuery::for()`).
- [Informational] `MeetingNoteFactory` (`forOccurrence()`, `blank()`) and `MeetingNoteSeeder` are complete and match the plan's fixture data — the seeded 12-week `Weekly sync` series carries a note on exactly one occurrence, confirmed via `migrate:fresh --seed`.
- [Informational] `MeetingNote::$guarded = []` is safe here: the only write paths are the Livewire component's own controlled properties (`#[Locked]` on the identity fields) and factories/seeders — no controller mass-assigns from request input.

**Verdict: approve**
