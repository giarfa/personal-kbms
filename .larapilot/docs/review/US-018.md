# US-018 — Review notes

**Spec:** Step to the previous or next occurrence of a series
**Branch:** `feature/US-018-series-neighbour-links` (TASK-00..TASK-05 plus plan bookkeeping and a review-fix commit, cut from `develop`)
**Effort:** `STANDARD` — Robert + Lars ran as parallel readonly sub-agents against the branch diff.

## Robert (code review)

- [Medium] `app/Meetings/SeriesNeighbourLookup.php` — the class docblock claimed "the series itself is never loaded, so the detail page's cost does not grow with how long the standing meeting has been running". `EXPLAIN QUERY PLAN` shows `SEARCH … USING INDEX calendar_events_source_uid_recurrence_id_unique (source_uid=?)` followed by `USE TEMP B-TREE FOR ORDER BY`: the index serves the equality only, then SQLite sorts the matched series rows before the limit. One *model* is hydrated per direction, so the spec's literal criterion holds, but the sort is proportional to the series. **Fixed** — the docblock now states exactly what the index buys and names the `(source_uid, starts_at, recurrence_id)` composite that would make it a true keyset seek, along with why it is out of scope here.
- [Medium] `tests/Feature/MeetingSeriesNavigationTest.php` — the query-count test's docblock claimed "a neighbour found by loading the series would pass every assertion above and fail this one". It would pass this one too: fetching the whole series in one query and picking the neighbour in PHP costs one query either way. **Fixed** — the docblock now says the test pins the count only (no N+1) and points at the `limit 1` SQL assertion in `SeriesNeighbourLookupTest` as the place the bound is actually proven.
- [Low] `tests/Feature/MeetingSeriesNavigationTest.php` — `countQueries()` registered a `DB::listen` callback per call and never removed it. **Fixed** — one listener registered in `setUp()` against a class property.
- [Low] `tests/Feature/MeetingSeriesNavigationTest.php` — `preg_match(...); $matches[0] ?? ''` failed open: a markup shift would make every `assertStringNotContainsString` pass vacuously. **Fixed** — extracted to `seriesNav()`, which asserts the match succeeded before returning.
- [Low] `tests/**/…SeriesNeighbour*` — test `recurrence_id` values (`20260901T090000Z`, `2026-09-15T090000Z`) were shapes `IcsParser::formatRecurrenceId()` never emits. **Fixed** — all fixtures now use the production forms, `Y-m-d\TH:i:s\Z` and `Y-m-d`.
- [Low] `tests/Unit/Meetings/SeriesNeighbourLookupTest.php` — `test_each_direction_costs_one_query_regardless_of_series_length` was fully subsumed by the bounded-lookup test built on the same fixture. **Fixed** — removed. Also removed an `assertInstanceOf` on a non-nullable typed property (a tautology), and made the SQL assertion driver-independent rather than hardcoding SQLite identifier quoting.
- [Low] `app/Meetings/SeriesNeighbour.php` — `accessibleName()` produced `"Previous occurrence,  (opens in a new tab)"` for an absent neighbour. Unreachable from the view, but a latent trap. **Fixed** — it now degrades to the bare direction, pinned by a test.
- [Low] `app/Http/Controllers/MeetingController.php` — two-line inline comment against the CLAUDE.md preference for PHPDoc; the fact was already stated on `SeriesNeighbourLookup::forOccurrence()`. **Fixed** — removed.
- [Low] `resources/views/components/meeting/series-nav.blade.php` — the renderer compared the `SeriesDirection` enum inline, against the plan's own "Blade stays a pure renderer" division, and outside the Larastan gate (Larastan does not scan Blade). **Fixed** — `SeriesNeighbour::isPrevious()`.
- [Low] `app/Meetings/SeriesNeighbour.php` — `format('D j M')` hardcoded English abbreviations while the surrounding strings went through `__()`. **Fixed** — `translatedFormat()`. No behaviour change today (the app ships English-only).
- [Low, open] `resources/views/components/meeting/series-nav.blade.php` — `aria-describedby` on a `disabled` button never fires, because a disabled button is not focusable. **Left as-is by design:** the acceptance criterion demands "the same shape as the existing 'Open in Outlook' fallback", the reason is a visible adjacent `kb-note-inline` span and therefore in the accessible document, and switching this control alone to `aria-disabled` would fork the project's "offered but inert" vocabulary. Worth revisiting for both controls together.
- [Low, open] `app/Meetings/SeriesNeighbourLookup.php` — if a feed promotes a previously non-recurring `UID` into a series, the stale `recurrence_id = ''` row survives until the cancellation sweep, stays in the chain, and can be reached as a neighbour — landing on a page that renders no navigation. Self-healing and vanishingly rare; no test covers a mixed-`recurrence_id` `source_uid`.
- [Low, open] git — TASK-03's commit carried `SeriesNeighbour::directionLabel()` (TASK-01 scope) and TASK-04's carried 32 lines of the TASK-02 unit test file. Still one commit per task with correct Conventional Commit subjects: scope bleed between commits, not batching.

## Lars (security)

- [Low, open] `app/Meetings/OccurrenceKey.php` — pre-existing, not introduced here but now reachable from more links: `decode()` accepts non-canonical base64 trailing bits, so several distinct route keys resolve the same occurrence (URL aliasing). Harmless in this app — no auth, no cache key, no rate limiter, no signed URL keyed on the segment — but the route key is not a canonical identifier. A `toRouteKey() === $key` round-trip check in `fromRouteKey()` would close it if canonicality ever matters.
- [Low] `app/Meetings/SeriesNeighbourLookup.php` — the same `TEMP B-TREE FOR ORDER BY` Robert found, read as resource consumption under a hostile feed: a `.ics` emitting a very large number of occurrences under one `UID` makes each render proportional to that series. Bounded in practice by the sync window. **Docblock corrected**; no index added, per the spec's scope.
- [Low, open] `tests/Feature/MeetingSeriesNavigationTest.php` — no test feeds a hostile `source_uid` / `recurrence_id` (`"><script`, `javascript:`, `/`, `..`) through the factory and asserts the rendered `href` and `aria-label` stay escaped. Correct today by construction (base64url + `e()`), but nothing pins it against a future change to `OccurrenceKey` encoding.
- [Info] No injection: the route key never reaches the new code as a string. `Route::bind('occurrence')` decodes it to an `OccurrenceKey` and resolves via `scopeForOccurrence`, which binds both columns as parameters. In the new query, column names are literals and the comparison/order operators derive solely from the `SeriesDirection` enum — never from request input.
- [Info] No XSS: the reason element id is `series-previous-reason` / `series-next-reason`, from the enum backing value — feed-carried values never reach an `id`. The `aria-label` interpolates only a `Carbon` date string. No `{!! !!}` in the new Blade; `href` is escaped by Flux's `button-or-link`.
- [Info] No dangerous-scheme exposure: no feed-carried URL is used here — the `href` is `route()`-generated and therefore internal by construction, so no allowlist is needed (unlike `OutlookLinkBuilder::isSafeUrl()`).
- [Info] No tabnabbing: `rel="noopener"` on both `target="_blank"` controls, asserted by test. The inert branch renders a `<button disabled>` with no `href`.
- [Info] No IDOR and no new addressable surface: every neighbour link targets `meetings.show` with a key sharing the current occurrence's `source_uid` — a strict subset of what the route already accepted. No new route, no middleware change.
- [Info] No dependency change, so no new `composer audit` surface. `SECURITY.md` / `security.txt` untouched and out of scope.
